Direct Peer-to-Peer Transfers via WebRTC

LAN Share connects browsers directly across your local Wi-Fi or Ethernet network using high-performance WebRTC DataChannels. Files and messages stream straight from sender to receiver without staging or routing through external cloud servers.

Streaming SHA-256 File Integrity Verification

Transfers are protected with on-the-fly streaming SHA-256 cryptographic verification. The receiver computes checksums chunk-by-chunk in real time, validating byte-level integrity against the sender hash upon completion.

Zero-Cloud Local Network Privacy

All transfers remain strictly local within your local area network (LAN). Lightweight WebSocket signaling orchestrates initial peer discovery and ICE candidate exchange, after which all media and payload streams flow directly over encrypted DTLS/SCTP channels.

Frequently Asked Questions & Direct Answers

How does LAN Share transfer files without cloud uploads?

LAN Share establishes direct browser-to-browser peer-to-peer WebRTC DataChannels using DTLS (Datagram Transport Layer Security) and SCTP over your local network. A lightweight Node.js/Socket.IO signaling server clusters devices by local subnet and STUN IP solely to relay ~2 KB of WebRTC handshake metadata (SDP offer/answer and ICE candidates). Once connected, all file data streams directly between devices across the local Wi-Fi or LAN. File contents never touch, transit, or get stored on any cloud server or intermediate database.

What is the file size limit on LAN Share?

LAN Share has no arbitrary file size limit. On desktop Chromium browsers (Google Chrome, Microsoft Edge), files stream directly to storage via the File System Access API (window.showSaveFilePicker), enabling multi-gigabyte transfers (e.g., 10 GB, 50 GB+) with minimal RAM consumption (< 50 MB). In browsers without File System Access API support (Apple Safari, Mozilla Firefox, Android browsers), received chunks assemble in memory up to ~2 GB to prevent browser memory exhaustion.

Is LAN Share secure?

Yes. All peer-to-peer data channels and chat messages are encrypted in transit using standard WebRTC DTLS encryption. File transfers remain entirely within your local network. LAN Share requires no user accounts, collects zero telemetry, uses no tracking cookies, and logs no file metadata. Additionally, bit-for-bit file integrity is cryptographically validated using chunked streaming SHA-256 checksums calculated independently on both the sender and receiver.

How does LAN Share handle router AP or Client Isolation?

On networks with router AP or Client Isolation enabled (such as hotel, airport, or university Wi-Fi) where direct peer UDP traffic is blocked, LAN Share's built-in 20-second connection watchdog flags the timeout and displays diagnostic guidance recommending a mobile hotspot or a configured TURN relay (VITE_TURN_URL).
